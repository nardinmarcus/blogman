# Retain the versionless write adapter and retire the ledger-only client bypass

The PUT `/api/admin/posts/[slug]` route is not a legacy direct write: it resolves the slug through the address registry (ADR 0009), refuses versionless articles and lifecycle publish requests with 409, and maps field changes onto the explicit command kernels with server-resolved expected versions. Its remaining value is serving stale admin clients during a deploy window, which is harmless; it is retained as the **versionless write adapter**. The client-side ledger-only bypass in `lib/article-command-client` (null identity facts → legacy PUT) was retired after verification that no reachable state benefits from it: canonical deployments always carry identity facts; a canonical-absent database receives a deliberate schema error (503) from the registry read, so admin writes are unsupported there by design — the bypass only changed the error message; and the earlier ledger-only tolerances (5339466, 64ef81f) concern the versioned read path, not this write surface. The bypass's `publishTemp` legacy mapping also embedded a label/action mismatch for temp-published articles (issue #19 class), now owned by the Publication Intent resolver. Future architecture reviews should not re-propose "legacy write compatibility" for either surface.
